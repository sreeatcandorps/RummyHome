# 12o: New game players step, with the keyboard up (mockups only; small phone = 360 dp × 1.3, Pixel 6 = 412 dp × 1.0)

**What is wrong.** On SDK 54 the app is drawn edge to edge, so the keyboard covers New game instead of shrinking it, and the screen gives the page no keyboard padding. Each pair of chips adds a 42 dp row, so at 7 picks on the small phone the search ends at 444 dp, the one result starts at 454 dp and the keyboard starts at 469 dp (`1-today-small.png`, the real CI frame from run 46065162206). On the Pixel 6 the result still shows at 7 picks (and at 13), but the Next bar is under the keyboard (`1-today-pixel6.png`, drawn from the code).
**Both options** pad the page by the keyboard's height, like `AuthShell` (12c). The proposal said to pad only the page, but the Next bar sits outside the scroller, so it would stay hidden. Here it rides on the keyboard with Next alone; the two tiles come back when the keyboard closes. This is D112's pattern for Add by initials. When the keyboard closes, the chips wrap in full again (`4-keyboard-closed-*.png`).
**A** (`2-option-a-*.png`): while typing, the chips become one row that scrolls sideways, scrolled to the end, so the newest pick and its × are on screen. A fade at the left shows there are more.
**B** (`3-option-b-*.png`): while typing, the chips become one line, "7 picked · Show ▾". Show closes the keyboard and the chips come back. B repeats the count that is already in the badge, and you need a tap to see a pick or take it back.
In both, the result sits 288–365 dp on the small phone, and Next sits at 392–469 dp, just above the keyboard.
**Recommendation: A.** Both take the same 36 dp, so B saves no room. A keeps the chips as they are, and the player you just picked stays one tap from ×.
**What the build touches:** `app/(screens)/games/new.tsx` gets `keyboardDidShow` / `Hide` listeners and a `keyboardUp` state. Its `Screen` and `BottomBar` go inside `KeyboardAvoidingView` with `behavior="padding"`, and the bar shows Next alone while the keyboard is up. `components/players/SelectedPlayersStrip.tsx` gets a `oneRow` prop: a horizontal `ScrollView` that calls `scrollToEnd` on a new pick, with testID `selected-strip-one-row`. Add players to game uses the same strip and gets the same collapse. A unit test covers the prop.
**Maestro:** `full/52-seating-13p.yaml` drops the 12 `hideKeyboard` + `scrollUntilVisible` pairs, so each pick is tapped with the keyboard up, which proves the fix. Its `when notVisible new-game-next → hideKeyboard` becomes a plain `assertVisible` of `new-game-next`, and after the 7th pick it asserts `selected-strip-one-row`. `chaos/c03-bad-input.yaml` keeps its `hideKeyboard`. Smoke 16, 19 and 24 never type, so they do not change.
Redraw with `node make.mjs` (`NODE_MODULES=` points at another checkout's `node_modules`). `src/picker.html` holds the sizes and `make.mjs` says where the keyboard images came from.
